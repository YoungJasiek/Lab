1. Architectural Philosophy & C++20 Standards

Lab Engine is designed from the ground up on modern C++20 principles, prioritizing explicit object lifetimes, zero-cost abstractions, deterministic execution, and zero unnecessary dynamic allocations during the gameplay frame loop.

Following 15 years of game development best practices, the engine enforces strict separation of concerns:

  • Modular Subsystems: Core logic, rendering (OpenGL 4.5+ DSA), physics, spatial collision, camera, input, and AI operate as decoupled, testable components.
  • Shared Engine Library: Compiled as LabEngineLib.lib, allowing both the game runtime (Lab.exe) and the 3D level editor (LabHammer.exe) to link against the exact same rendering, math, and map serialization code.
  • Zero Global Spaghetti: No global OpenGL mutable state or hidden singletons. Systems receive dependencies explicitly via constructors and service locators.

2. Deterministic Frame Loop & Physics Accumulator

The engine main loop in src/LabCore.cpp utilizes a semi-fixed timestep physics accumulator. High-resolution frame delta time is captured via glfwGetTime(), and physics updates are integrated in discrete fixed steps (dt = 1.0f / 60.0f) inside onFixedUpdate(): 

float newTime = static_cast<float>(glfwGetTime());
float frameTime = newTime - currentTime;
currentTime = newTime;

// Clamp accumulator to prevent spiral of death
if (frameTime > 0.25f) frameTime = 0.25f;
accumulator += frameTime;

while (accumulator >= FIXED_DT) {
    onFixedUpdate(FIXED_DT);
    accumulator -= FIXED_DT;
}

// Alpha interpolation factor for ultra-smooth rendering at any refresh rate
float alpha = accumulator / FIXED_DT;
onRender(alpha);

This guarantees reproducible collision physics, consistent jump heights, and deterministic projectile trajectories regardless of whether the user plays at 60Hz, 144Hz, or 360Hz.

3. Memory Safety & Zero Runtime Allocations

Memory ownership throughout the engine adheres strictly to the C++ Core Guidelines:

  • Exclusive Ownership: Managed with std::unique_ptr<T> for shaders, textures, and mesh instances. Destructors automatically release GPU and OS handles (e.g. glDeleteTextures, glDeleteBuffers).
  • Non-Owning Views: Handled via std::span<T> and const T& rather than raw pointer arithmetic, eliminating dangling pointer bugs and out-of-bounds reads.
  • Zero Runtime Allocations: Vectors, particle pools, and entity buffers are pre-allocated and reserved upon level load. No malloc, free, new, or delete occur during active combat frames.

4. Combat Subsystem & Bot AI Finite State Machine

The combat engine in src/LabCombat.cpp coordinates weapons, ballistics, and bot AI routines:

  • Critical Headshots: Bounding boxes are segmented into head (boxMin.y + 0.75f * height) and torso regions. Head hits apply a 3.0x damage multiplier with distinct acoustic feedback.
  • Combat AI States: Bots execute a continuous finite state machine (FSM):
    • State::Patrol – Navigates between map waypoint spawners.
    • State::Alert – Investigates weapon firing noises and player footstep traces.
    • State::CombatChase – Closes distance while maintaining line-of-sight.
    • State::SuppressFire – Fires bursts from behind pillar cover.

5. Spatial Physics & Branchless Ray-AABB Intersection

The collision engine implemented in include/LabCombat.h uses the branchless Kay-Kajiya Slab Algorithm for testing hitscan bullet rays and camera picking against Axis-Aligned Bounding Boxes (AABB).

By computing the reciprocal ray direction vector invDir = 1.0f / rayDir once, axis intersection intervals are computed using vector min/max operations without branching: 

t0 = (boxMin - rayOrigin) * invDir;
t1 = (boxMax - rayOrigin) * invDir;
tNear = max(min(t0.x, t1.x), min(t0.y, t1.y), min(t0.z, t1.z));
tFar  = min(max(t0.x, t1.x), max(t0.y, t1.y), max(t0.z, t1.z));

If tNear <= tFar and tFar >= 0.0f, an intersection occurs at distance tOut = tNear. The surface normal is extracted directly based on which axis slab was penetrated, providing immediate contact data for ricochet sparks and bullet hole decals.

6. LabPhysics: 3D Rigid Body Dynamics & Destruction

Introduced in Sprint 5, LabPhysics implements full 3D Newtonian dynamics:

  • RigidBody Mechanics: Integration via semi-implicit Euler, diagonalized local moment of inertia tensor for arbitrary box extents, linear and angular velocity damping, and dynamic resting sleep thresholding to minimize CPU cycles.
  • OBB/AABB Contact Manifolds: Robust collision queries between physical props and world static brushes with normal impulse resolution, elastic restitution, and kinetic/static friction coefficients.
  • Destructible Props (PropType::Crate): Wooden crates with 40 HP health pool that shatter on destruction into 7 discrete physical wooden planks, each receiving kinetic blast impulses and tumbling with independent angular velocities.
  • Explosive Fuel Barrels (PropType::ExplosiveBarrel): Volatile red cylinders detonating from bullet impacts, melee strikes, or shockwaves. Produces a 6.5m radial explosion dealing up to 130 damage, triggering cascading chain reactions among adjacent barrels and flinging enemy bots into ragdoll flight.

7. LabAudio: 3D Spatial Audio & Synthesizers (miniaudio)

The audio engine links the modern, zero-dependency miniaudio v0.11.25 library:

  • Procedural 16-Bit PCM WAV Synthesizers: Self-contained in-memory generators producing all 26 game audio effects (FM synthesis, filtered pink/white noise, ADSR envelope shaping) with zero external audio asset dependencies.
  • Complete Weapon & World Foley: 9 unique firearm blasts, dry-fire clicks, magazine drops, shell casing tumbles, pipe swings, footstep variations (concrete, metal grating, snow/ice), medkits, ammo pickups, and barrel detonations.
  • 3D Spatial Attenuation: Real-time distance inverse-square falloff, stereo panning, and Doppler directional vectors calculated from the player's camera orientation.
  • Thread-Safe Voice Pool: Fixed 64-voice memory-safe sound pool operating without heap allocations during active firefights.

8. LabInteractive: In-World Terminals & Trigger Logic

The interactive entity system in src/LabInteractive.cpp brings tactical world interactions:

  • Raycast Picking (+use): Continuous 2.8-meter view frustum raycast picking allowing players to operate in-world consoles, keypads, and industrial breaker switches by pressing E.
  • Security Clearance Logic: State machine managing Locked, Unlocked, and Active states with visual LED indicators (red, green, cyan) and procedural audio feedback (Access Granted chime, Access Denied buzz).
  • 3D CRT Screens & Logic I/O: Procedural raster scanlines, telemetry status bars, and dispatch of activation signals directly to target sliding airlocks and bunker blast doors.

9. LabCSG: Sutherland-Hodgman Polygon Clipping

The CSG geometry engine in src/LabCSG.cpp powers real-time constructive solid geometry:

  • Convex Polyhedron Slicing: Multi-pass Sutherland-Hodgman polygon clipping against an arbitrary 3D cutting plane defined by user vectors in LabHammer.
  • Cap Triangulation: Automatic fan triangulation of the cross-section plane with unified outward surface normals and counter-clockwise vertex winding (CCW).
  • Planar UV Mapping: Seamless generation of Source-style texture projection coordinates across sliced faces without texture stretching or warping.

10. LabDecals: Projective Decals with Depth Bias

The decal projection subsystem in src/LabDecals.cpp generates persistent surface impacts:

  • Surface Projection: Projects tangent-space decals directly onto brushes, polyhedra, doors, and static geometry based on raycast collision normal vectors.
  • Depth Bias without Z-Fighting: Employs glPolygonOffset(-2.0f, -2.0f) combined with a 2.5mm surface normal push and glDepthMask(GL_FALSE) to eliminate surface flickering.
  • Procedural Decal Atlas: 64x64 RGBA impact craters for concrete, metal bullet punctures with silver burrs, organic blood splatters, and charred explosion scorch marks.
  • Circular Instance Buffer: Manages up to 256 active decals with smooth alpha fadeout during the final 5 seconds of their lifetime.

11. LabSkeletal: glTF 2.0 Rig & GPU Vertex Skinning

The skeletal animation subsystem in src/LabSkeletal.cpp delivers character articulation:

  • glTF 2.0 Rigging: 20-bone humanoid skeleton hierarchy (Root, Pelvis, Spine, Torso, Neck, Head, Clavicles, Arms, Hands, Legs, Feet).
  • Quaternion Math & SLERP: Custom Quat implementation providing smooth spherical linear interpolation between animation keyframes (Idle, Walk, Run, Shoot, Melee).
  • Bone Socket Attachment: Hybrid glTF + STL architecture dynamically binding rigid 3D weapon meshes (e.g. pipe.stl, weapon_pistol) to hand joint sockets with animated position and rotation matrices.

include/LabCombat.h – Branchless Ray-AABB Slab Algorithm 
#pragma once
#include "LabMath.h"

namespace Lab {
    class Raycast {
    public:
        // Branchless Ray-AABB intersection algorithm with normal extraction
        static bool rayIntersectAABB(const Vec3& rayOrigin, const Vec3& rayDir,
                                     const Vec3& boxMin, const Vec3& boxMax,
                                     float& tOut, Vec3* outNormal = nullptr) {
            Vec3 invDir{ 1.0f / (rayDir.x != 0.0f ? rayDir.x : 1e-8f),
                         1.0f / (rayDir.y != 0.0f ? rayDir.y : 1e-8f),
                         1.0f / (rayDir.z != 0.0f ? rayDir.z : 1e-8f) };

            Vec3 t0 = (boxMin - rayOrigin) * invDir;
            Vec3 t1 = (boxMax - rayOrigin) * invDir;

            Vec3 tmin = minVec3(t0, t1);
            Vec3 tmax = maxVec3(t0, t1);

            float tNear = std::max({ tmin.x, tmin.y, tmin.z });
            float tFar  = std::min({ tmax.x, tmax.y, tmax.z });

            if (tNear > tFar || tFar < 0.0f) return false;

            tOut = (tNear >= 0.0f) ? tNear : tFar;
            return true;
        }
    };
}
