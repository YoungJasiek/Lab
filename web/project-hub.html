1. Overview & Engine Main Menu

The Project Hub acts as the central gateway and main menu for the Lab Engine. Rather than hardcoding a single game into the engine executable, Lab operates as a true general-purpose engine:

  • Project Launching: Launch existing projects, continue recent sessions, or open projects from anywhere on disk.
  • Clean Project Lifecycle: Create brand new 2D or 3D games with a single click, complete with boilerplate configs, maps, and asset folders.
  • Non-Destructive Switching: Switch active projects inside LabEditor.exe seamlessly without restarting the software or losing project settings.
  • Release Purity: Engine distribution binaries (Release builds) contain only the clean engine toolset, while games remain independently packaged.

2. Engine vs Game Asset Decoupling

A critical architectural milestone was achieved by strictly isolating engine-internal assets from game-specific resources:

Resource Category Physical Location Virtual Prefix Contents & Scope
Engine Assets engine/assets/ engine:// Default shaders (Blinn-Phong, grid, skybox), engine fallback textures (missing texture checkerboard), editor icons, and core UI fonts.
Game Assets games/<project>/assets/ or Documents/LabGames/<project>/assets/ game:// Levels (.labmap), audio, 3D models, textures, skyboxes, and HUD layouts (.labhud) specific to the user's game.
Drop-in Plugins plugins/ filesystem Standalone Lua plugins (1 file = 1 plugin) managed via the Package Manager.
Core Scripts scripts/ filesystem Engine-level automation and balance scripts.

This decoupling guarantees that CMake builds never contaminate user game code with engine dependencies, and game developers can freely version control their games in separate repositories.

3. Virtual URI Resolution (engine:// vs game://)

Lab introduces a unified virtual URI abstraction implemented in LabProject::resolvePath(): 

// Resolving engine-internal resource
std::string fontPath = ProjectManager::resolvePath("engine://fonts/segoeui.ttf");
// -> "C:/Lab/engine/assets/fonts/segoeui.ttf"

// Resolving game-specific level or HUD
std::string mapPath = ProjectManager::resolvePath("game://assets/maps/cryo_complex.labmap");
// -> "C:/Users/.../Documents/LabGames/FrozenLife/assets/maps/cryo_complex.labmap"

If a requested game asset does not exist, the resolver automatically falls back to the corresponding engine:// asset, preventing runtime null-pointer crashes while logging clear diagnostic warnings.

4. Project Management, Creation & Discovery

ProjectManager automatically discovers available projects from two primary locations:

  1. Built-in Showcase Games: games/* located within the engine installation (e.g., games/frozen_life/).
  2. User Projects: Documents/LabGames/* on Windows (or ~/LabGames/* on Linux), keeping user game assets entirely separate from CMake build artifacts.

Project Manifest Specification (project.labproject)

Every project folder contains a JSON manifest detailing metadata and default parameters:

{
  "id": "frozen_life",
  "name": "Frozen-Life (3D Showcase)",
  "version": "1.0.0",
  "author": "Lab Engine Team",
  "defaultMap": "assets/maps/cryo_complex.labmap",
  "defaultHud": "assets/hud/frozen_life_hud.labhud",
  "genre": "FPS",
  "dimension": "3D",
  "entryScript": "scripts/game_init.lua"
}

5. Automated One-Click Standalone Exporter

Building a release game for players no longer requires manual file copying. In the Project Hub or via Ctrl+B, the Automated Exporter creates an independent shipping package:

🚀 Standalone Distribution Output

The exporter automatically packages:

  • LabPlayer.exe – Stripped standalone runtime player.
  • All 10 Engine DLLs (LabCore.dll, LabRender.dll, etc.) – Automatically copied to the destination folder.
  • game.config – Configured with default map, HUD, resolution, and audio settings.
  • assets/ – Cloned and optimized game assets (maps, textures, audio, HUDs).
  • run_game.bat – Instant launcher script for players.

6. Frozen-Life Decoupled Showcase & Demo Bundle

Frozen-Life (FL) is the engine's premier showcase game, now completely decoupled and structured according to the new standards:

  • Project Root: games/frozen_life/
  • Native HUD Restored: assets/hud/frozen_life_hud.labhud with SUIT 0%, HEALTH 150, Ammo indicators, and Cryo Complex Outpost badge.
  • Standalone Demo Package: Pre-built standalone demo located in games/frozen_life/demo/. Users can run the demo directly via run_demo.bat without opening the editor!
  • Continuous Verification: Test 80 in the automated suite explicitly asserts the validity of the Frozen-Life manifest, default map, and native HUD.
