1. Scripting Architecture & Script Locations

The LabScript subsystem embeds a sandboxed, high-performance Lua 5.4.6 virtual machine directly into LabEngineLib. This completely decouples high-level gameplay rules, entity logic, UI state, and custom mod commands from C++ engine compilation.

Scripts are automatically discovered and loaded from three primary locations:

  • Addon Startup Hooks (addons/<mod_name>/scripts/startup.lua): Executed when the user activates an addon or mod package. Ideal for registering custom console commands, ConVars, input bindings, and initializing HUD widgets.
  • Map Entity Scripts (assets/scripts/*.lua): Linked directly to brushes, props, doors, cameras, and sprites in .lmap files or inside LabHammer via the script entity property. Executed automatically when a map is loaded.
  • Central Gameplay Rules (assets/scripts/game_mechanics.lua): Defines core constants for player mechanics, weapon ballistics, medkits, ammo, and biometric scanner authorization.

2. Engine Lifecycle & Event Callbacks

The native engine invokes specific global Lua functions when key simulation events occur. Modders implement these functions to respond to frame ticks, collisions, damage calculation, and mission progress.

Callback Function Parameters Returns Description
OnGameStartup() none none Invoked when an addon startup script is executed via executeStartupHook(). Use to initialize mod state, register cvars, and prime HUD widgets.
OnUpdate(dt) dt (number – seconds) none Invoked every simulation frame during gameplay and editor simulation mode. Ideal for continuous animation, patrol movements, and custom timers.
OnTriggerEnter(entityId, otherEntityId) entityId (integer), otherEntityId (integer) none Triggered when a physics trigger volume or collision overlap occurs between two entities (e.g. player entering a door sensor, keycard pickup zone).
CalculateDamage(incomingDamage, currentArmor, currentHealth) incomingDamage (number), currentArmor (number), currentHealth (number) finalDamage (number), absorbed (number), isLethal (boolean) Evaluates incoming damage and armor absorption ratio. Modders can completely customize damage calculations, armor degradation curves, and invulnerability shields.
MissionProgress(cardsCollected, timeLeft) cardsCollected (integer), timeLeft (number) status (string – e.g. "WIN", "LOSE", "RUNNING"), message (string) Called periodically to evaluate level progression goals, keycard counts, and round countdowns.
OnRetinalScanComplete(scannerId, linkedDoorIndex) scannerId (integer), linkedDoorIndex (integer) authorized (boolean) Triggered when an interactive retinal scanner entity finishes scanning. Return true to grant clearance and unlock associated doors. 
-- Example: Implementing Engine Lifecycle Callbacks
function OnGameStartup()
    Lab.log("Addon 'Tactical Insertion' activated successfully!")
    HUD.setText("mission_title", "SECTOR 14 // RECON")
    HUD.setVisible("mission_title", true)
end

function OnUpdate(dt)
    -- Rotate a custom beacon or animate an entity
    local beacon = World.getEntity("SecurityBeacon")
    if beacon then
        beacon:move(0, math.sin(dt * 2.0) * 0.1, 0)
    end
end

function OnTriggerEnter(entityId, otherEntityId)
    Lab.log("Overlap: Entity #" .. tostring(entityId) .. " hit Entity #" .. tostring(otherEntityId))
    if entityId == 101 then
        Lab.playSound(25, 0.8)
        HUD.setText("quest_banner", "Keycard collected!")
    end
end

function CalculateDamage(incomingDamage, currentArmor, currentHealth)
    local ratio = 0.70 -- 70% absorbed by suit armor
    local absorbed = 0.0
    if currentArmor > 0.0 then
        absorbed = math.min(currentArmor, incomingDamage * ratio)
    end
    local finalDmg = incomingDamage - absorbed
    local isLethal = (currentHealth - finalDmg <= 0.0)
    return finalDmg, absorbed, isLethal
end

3. Core Engine Library (Lab.*)

The Lab global table provides foundational host engine utilities including logging, spatial audio playback, map door unlocking, and multiplayer server chat broadcasting.

Command Parameters Returns Description
Lab.log(message) message (string) none Writes an informational message to the engine log file and editor terminal with [Lua] prefix.
Lab.playSound(soundId, [volume]) soundId (integer), volume (number – default 1.0) none Plays an audio clip via the audio.dll spatial sound engine by its SoundID enum (e.g. UI click, alarm, gunshot).
Lab.unlockDoor(doorIndex) doorIndex (integer) none Unlocks a map door by its brush/door entity index, triggering the engine host door unlock callback.
Lab.addChatMessage(sender, text) sender (string), text (string) none Broadcasts a chat or radio announcement into the server/multiplayer HUD chat buffer. 
-- Example: Lab core utilities
Lab.log("Initializing Cryo Security Override...")
Lab.playSound(14, 0.75) -- Play access chime
Lab.unlockDoor(2)       -- Unlock blast door #2
Lab.addChatMessage("[SECURITY BOT]", "Sector 14 Quarantine Lifted.")

4. Console, ConVars & Commands (Console.*)

Lab features a Source Engine-inspired developer console accessible with the ~ (Tilde) key. Modders can dynamically register their own console commands and persistent ConVars in Lua! Both Console.* and lowercase console.* are registered as aliases.

Command Parameters Returns Description
Console.register_command(name, callback, [helpText], [flags])
Alias: registerCommand		 name (string), callback (function), helpText (string), flags (integer) none Registers a custom command into the engine console. When invoked, the callback receives an args table where args[1] is the command name, args[2] is the 1st parameter, etc. Automatically flagged with FCVAR_MOD.
Console.register_cvar(name, [defaultVal], [helpText], [flags])
Alias: registerCvar		 name (string), defaultVal (string – default "0"), helpText (string), flags (integer) none Registers a modding ConVar into ConVarRegistry with FCVAR_MOD | FCVAR_ARCHIVE flags. Persisted in config files.
Console.get_cvar(name)
Alias: getCvar		 name (string) value (string or nil) Retrieves the current string value of any engine or mod ConVar (e.g. "sp_speed", "r_bloom").
Console.set_cvar(name, value)
Alias: setCvar		 name (string), value (string) success (boolean) Modifies the value of an existing ConVar dynamically. Returns true if found and modified.
Console.execute(commandString) commandString (string) success (boolean) Executes any native console command string (e.g. "sp_cheats 1", "god 1", "wrd_restart").
Console.print(text) text (string) none Prints text directly to the in-engine console window scrollback. 
-- Example: Registering Custom Mod Commands & ConVars
Console.register_cvar("mod_grav_multiplier", "1.0", "Custom gravity multiplier for Cryo mod")

Console.register_command("mod_teleport", function(args)
    -- args[1] is the command itself ("mod_teleport")
    local targetName = args[2] or "Player"
    local x = tonumber(args[3]) or 0.0
    local y = tonumber(args[4]) or 2.0
    local z = tonumber(args[5]) or 0.0

    local ent = World.getEntity(targetName)
    if ent then
        ent:setPosition(x, y, z)
        Console.print("Teleported entity '" .. targetName .. "' to (" .. x .. ", " .. y .. ", " .. z .. ")")
    else
        Console.print("Error: Entity '" .. targetName .. "' not found!")
    end
end, "Teleports an entity: mod_teleport    ")

-- Execute existing engine commands programmatically
Console.execute("sp_cheats 1")
Console.execute("cam_fov 100")

5. Unified Input & Action System (Input.*)

The Input global table connects directly to Lab's InputActionManager, allowing script authors to define action mappings (buttons, keys) and analog axes (mouse, sticks) with keyboard and gamepad binding support.

Command Parameters Returns Description
Input.registerAction(name, [desc], [defaultKey], [defaultGamepadButton]) name (string), desc (string), defaultKey (string or int), defaultGamepadButton (string) none Registers a named action event (e.g. "Sprint", "Flashlight") with default bindings (e.g. "Shift", "ButtonA").
Input.registerAxis(name, [desc], [posKey], [negKey], [gamepadAxis]) name (string), desc (string), posKey, negKey, gamepadAxis none Registers an analog axis mapped to positive/negative keys and a gamepad stick axis (e.g. "Throttle", "W", "S", "LeftY").
Input.isActionPressed(name) name (string) pressed (boolean) Returns true while the action button or key is held down.
Input.isActionJustPressed(name) name (string) justPressed (boolean) Returns true only in the single frame the action was pressed down (rising edge).
Input.isActionJustReleased(name) name (string) justReleased (boolean) Returns true only in the frame the action was released (falling edge).
Input.getAxis(name) name (string) value (number – [-1.0, 1.0]) Returns axis value. Supports "MouseX" and "MouseY" for raw delta mouse movement.
Input.bindKey(actionName, key) actionName (string), key (string or int) none Binds a keyboard key (e.g. "Space", "E", "F", "LeftShift") to an action.
Input.bindGamepadButton(actionName, button) actionName (string), button (string) none Binds a controller button (e.g. "A", "B", "X", "Y", "Start", "LeftBumper").
Input.bindGamepadAxis(axisName, gamepadAxis) axisName (string), gamepadAxis (string) none Binds a physical gamepad axis (e.g. "LeftX", "LeftY", "RightX", "RightY", "LeftTrigger").
Input.saveBindings(filepath) filepath (string) success (boolean) Saves current action mappings and keybindings to a config file on disk.
Input.loadBindings(filepath) filepath (string) success (boolean) Loads custom keybindings from a configuration file. 
-- Example: Action registration and frame query
Input.registerAction("Flashlight", "Toggles suit flashlight", "F", "Y")
Input.registerAxis("MoveForward", "Forward movement axis", "W", "S", "LeftY")

function OnUpdate(dt)
    if Input.isActionJustPressed("Flashlight") then
        Lab.playSound(5, 0.9) -- Click sound
        local light = World.getEntity("SuitFlashlight")
        if light then
            light:setActive(not light:isActive())
        end
    end

    local moveY = Input.getAxis("MoveForward")
    local mouseDeltaX = Input.getAxis("MouseX")
end

6. Dynamic HUD & UI Canvas Bridge (HUD.*)

The HUD table establishes a live bridge between Lua scripts and the hud.dll 2D canvas. Modders can update text labels, health bars, quest objectives, countdown timers, and control widget visibility in real time.

Case-Insensitive API Parity: All HUD functions are registered with both camelCase (e.g. setText) and PascalCase (e.g. SetText) aliases to ensure seamless compatibility with existing community mods and addons.
Command Parameters Returns Description
HUD.setText(id, text)
Alias: SetText		 id (string), text (string) none Sets the text content of a HUD element by its element ID in the active HUD layout (e.g. "rpg.mana", "timer_text").
HUD.getText(id)
Alias: GetText		 id (string) text (string) Retrieves the current string value of a HUD element. Returns "" if not found.
HUD.setValue(id, number)
Alias: SetValue		 id (string), number (number) none Sets a numerical value used by progress bars, health gauges, stamina meters, or alpha levels.
HUD.getValue(id)
Alias: GetValue		 id (string) value (number) Queries the current floating-point value assigned to a HUD element.
HUD.setVisible(id, boolean)
Alias: SetVisible		 id (string), boolean (boolean) none Controls the visibility of a HUD element or container widget (true to show, false to hide).
HUD.isVisible(id)
Alias: IsVisible		 id (string) visible (boolean) Returns true if the HUD widget is currently visible. Defaults to true. 
-- Example: Updating game HUD in Lua
HUD.SetText("quest_status", "CARDS: 2 / 3")
HUD.SetValue("suit_oxygen", 84.5)
HUD.SetVisible("boss_healthbar", false)

-- Dynamic mission timer inside OnUpdate
local timeLeft = 120.0
function OnUpdate(dt)
    timeLeft = math.max(0, timeLeft - dt)
    local mins = math.floor(timeLeft / 60)
    local secs = math.floor(timeLeft % 60)
    HUD.setText("mission_timer", string.format("%02d:%02d", mins, secs))
    if timeLeft == 0 then
        HUD.setText("mission_status", "CRYO CORE OVERHEATED")
    end
end

7. World & Entity Spawning (World.*)

The World global table provides access to scene entities, map objects, scene nodes, and spawning primitives.

Command Parameters Returns Description
World.getEntity(name) name (string) entityTable or nil Finds an entity by its unique name in the active scene or map. Returns an entity handle with manipulation methods.
World.createEntity(name, [tag]) name (string), tag (string – optional) success (boolean) Creates a new entity in the active LabScene with the specified name and tag.
World.moveEntity(name, dx, dy, dz) name (string), dx, dy, dz (numbers) none Directly translates an entity's 3D position by the given delta vector without requiring an entity handle.
World.getSceneNode(name) name (string) nodeTable or nil Inspects the scene graph node hierarchy. Returns a table containing { name, worldX, worldY, worldZ }.

8. Entity Object Interface & Components

Entity objects returned by World.getEntity(name) or scene.findByName(name) expose an object-oriented method table for full scene manipulation.

Entity Method Parameters Returns Description
ent:setPosition(x, y, z) x, y, z (numbers) none Sets the entity's 3D position in world space coordinates.
ent:getPosition() none x, y, z (3 numbers) Returns 3 separate numbers representing coordinates in world space.
ent:move(dx, dy, dz) dx, dy, dz (numbers) none Translates the entity relative to its current position.
ent:getX(), ent:getY(), ent:getZ() none val (number) Returns the single X, Y, or Z coordinate value.
ent:setX(x), ent:setY(y), ent:setZ(z) val (number) none Sets a single coordinate axis without modifying the others.
ent:getTag() none tag (string) Returns the entity's assigned tag (e.g. "Enemy", "Pickup", "Door").
ent:setTag(tag) tag (string) none Changes the entity's tag.
ent:isActive() none active (boolean) Returns whether the entity is active and simulated in the scene.
ent:setActive(boolean) active (boolean) none Enables or disables the entity (hides renderer and skips physics tick).
ent:hasComponent(name) name (string) has (boolean) Checks if the entity possesses a component. Supports: "Camera", "Light", "AudioSource", "Cloth", "WaterVolume", "ForceField", "Vehicle", "Decal", "PostProcess", "Transform".
ent:getParent() none parentName (string or nil) Returns the name of the parent entity in the scene hierarchy.
ent:setParent(parentName) parentName (string or nil) none Attaches the entity as a child to parentName in the scene graph (or pass nil to unparent).
ent.transform table properties & methods Direct access to transform tables: position = {x, y, z}, rotation = {x, y, z, w}, scale = {x, y, z}, lookAt(target), rotate(axis, deg). 
-- Example: Entity inspection and hierarchy manipulation
local turret = World.getEntity("AutoTurret_01")
if turret then
    local x, y, z = turret:getPosition()
    turret:setPosition(x, y + 0.5, z)

    -- Attach spotlight to turret head
    local spot = World.getEntity("TurretLight")
    if spot then
        spot:setParent("AutoTurret_01")
    end

    -- Orient transform towards player
    local player = scene.findByName("Player")
    if player then
        turret.transform:lookAt(player.transform.position)
    end
end

9. Scene Graph Queries (scene.*)

The scene table provides high-level ECS queries matching modern game engines. Both scene.method() and object-style scene:method() calls are supported.

Command Parameters Returns Description
scene.findByName(name)
Alias: FindByName		 name (string) entityTable Finds an entity by name and synchronizes its transform position from the active C++ world scene.
scene.findByTag(tag)
Alias: FindByTag		 tag (string) entityTable Finds an entity tagged with the specified identifier (e.g. "MainCamera", "RespawnPoint").
scene.createEntity([name])
Alias: CreateEntity		 name (string – default "Entity") entityTable Spawns and returns a new entity table in the script environment.

10. Camera & Cinecam Controller (Camera.*)

The Camera table manages viewport perspective, cinematic cutscene cameras, field-of-view, and position/rotation in 3D space.

Command Parameters Returns Description
Camera.setActive(cameraName)
Global: setActiveCamera(name)		 cameraName (string) none Switches the active rendering viewport to the specified named camera entity (e.g. "cam_fps", "cam_cutscene").
Camera.getActive()
Global: getActiveCamera()		 none cameraName (string) Returns the name of the currently active camera entity.
Camera.setFov(cameraName, fov) cameraName (string), fov (number – degrees) none Modifies the field-of-view of the target camera (e.g. 75.0 for standard, 40.0 for sniper zoom).
Camera.setPosition(cameraName, x, y, z) cameraName (string), x, y, z (numbers) none Sets the 3D position coordinates of the specified camera entity.
Camera.setRotation(cameraName, pitch, yaw, roll) cameraName (string), pitch, yaw, roll (numbers – degrees) none Sets camera orientation in Euler angles (pitch, yaw, roll in degrees).
Camera.get(cameraName) cameraName (string) camTable or nil Returns a table with properties: { name, fov, active, follow_target, x, y, z, pitch, yaw, roll }. 
-- Example: Switching to a cinematic intro camera
Camera.setActive("cam_intro_rail")
Camera.setFov("cam_intro_rail", 85.0)
Camera.setPosition("cam_intro_rail", 12.0, 4.5, -30.0)
Camera.setRotation("cam_intro_rail", 10.0, 180.0, 0.0)

local info = Camera.get("cam_intro_rail")
if info then
    Lab.log("Active cam FOV is: " .. tostring(info.fov))
end

11. Math & Linear Algebra (quat, Vec3)

Lab exposes lightweight 3D math primitives for quaternions and vectors:

Function Parameters Returns Description
quat.fromEuler(pitch, yaw, roll)
Alias: Quat.fromEuler		 pitch, yaw, roll (numbers – degrees) { x, y, z, w } Converts pitch, yaw, and roll Euler angles (in degrees) into a normalized 4-component quaternion table.
Vec3.Lerp(a, b, t)
Alias: Vec3.lerp		 a (array/vector), b (array/vector), t (number – [0, 1]) { x, y, z } Linearly interpolates between vector a and vector b with interpolation factor t clamped between 0.0 and 1.0. 
-- Example: Smooth interpolation of camera position

-- Quaternion from Euler rotation

local ent = World.getEntity("PropSatellite")
if ent then
    ent.transform.rotation = q
end

13. Modder's Step-by-Step Recipes

Recipe A: Standalone Addon with Startup Hook

Create a file named addons/cryo_speedrun/scripts/startup.lua:

-- addons/cryo_speedrun/scripts/startup.lua
function OnGameStartup()
    Lab.log("[Speedrun Mod] Loaded successfully!")
    HUD.setText("mod_banner", "SPEEDRUN MODE ACTIVE")
    HUD.setVisible("mod_banner", true)

    -- Register a reset speedrun command
    Console.register_command("speedrun_reset", function(args)
        Console.execute("wrd_restart")
        HUD.setText("mod_banner", "SPEEDRUN RESTARTED")
    end, "Resets current speedrun attempt")
end

OnGameStartup()

Recipe B: Moving Elevator Entity

Attach this script to an elevator brush entity in LabHammer:

-- assets/scripts/elevator_platform.lua
local moveSpeed = 2.0
local maxY = 15.0
local minY = 1.0
local direction = 1.0

function OnUpdate(dt)
    local lift = World.getEntity("CargoElevator")
    if not lift then return end

    local y = lift:getY()
    if y >= maxY then direction = -1.0 end
    if y <= minY then direction = 1.0 end

    lift:move(0, direction * moveSpeed * dt, 0)
end

Recipe C: Security Keycard Trigger Zone

-- assets/scripts/keycard_trigger.lua
local cardCollected = false

function OnTriggerEnter(entityId, otherEntityId)
    if cardCollected then return end

    -- Check if overlap is with Player (Entity #0)
    if otherEntityId == 0 then
        cardCollected = true
        Lab.playSound(25, 1.0)
        Lab.unlockDoor(3) -- Unlocks BlastDoor_03
        HUD.setText("objective_text", "Keycard Verified. Door 3 Unlocked.")
        Lab.addChatMessage("[FACILITY]", "Clearance granted to Sector 3.")

        -- Deactivate pickup visual model
        local pickup = World.getEntity("KeycardVisual")
        if pickup then pickup:setActive(false) end
    end
end

14. Sandbox Security & Performance

To ensure stability and protect player systems when running untrusted community addons and downloaded workshop maps, Lab enforces strict sandbox boundaries:

  • Blocked OS Calls: os.execute, os.remove, os.rename, os.exit, os.setenv, and os.tmpname are completely stripped.
  • No Direct Host I/O: The global io table, dofile, loadfile, and package.loadlib are removed to prevent arbitrary filesystem tampering. File loading is mediated solely through the engine's virtual filesystem (VFS).
  • Protected Execution (pcall): All script evaluations, update ticks, and console commands are encapsulated in protected Lua calls (lua_pcall). Script runtime errors produce clean diagnostic log messages ([Lua Error]) rather than terminating the host application.
  • Ahead-Of-Time Bytecode (.luac): Release titles can precompile Lua scripts to standard Lua 5.4 stripped bytecode via compileLuaToBytecode(), providing near-instant loading times with zero runtime lexical parsing overhead.

Press Ctrl+R inside LabEditor or execute executeString() to hot-reload all modified Lua scripts live into the active simulation without restarting your game or losing level progress.

1. Scripting Architecture & Rationale

Hardcoding weapon damages, player walk speeds, jump impulses, and bot reaction intervals into C++ source code leads to long compilation cycles and prevents game designers from tuning feel in real time.

The LabScript subsystem embeds a pure C Lua 5.4 virtual machine directly into the engine, decoupling gameplay tuning completely from core executable compilation.

2. Decoupled Game Balance (scripts/balance.lua)

All gameplay balance parameters are defined in scripts/balance.lua: 

-- scripts/balance.lua
Balance = {
    Player = {
        walkSpeed = 5.5,
        sprintSpeed = 8.5,
        jumpImpulse = 6.2,
        gravity = -18.5,
        maxHealth = 100
    },
    Weapons = {
        M4A4S = { damage = 32.0, rpm = 660, clip = 30, range = 75.0 },
        Shotgun = { pellets = 8, damagePerPellet = 14.0, spread = 0.045 },
        Railgun = { damage = 150.0, cooldown = 1.5, pierceCount = 3 },
        Minigun = { damage = 18.0, rpm = 920, spinUpTime = 0.25 }
    },
    Bots = {
        reactionTime = 0.18,
        headshotMultiplier = 2.5,
        strafingFrequency = 1.2
    }
}

3. Interactive Developer Console (~ Key)

Pressing the Tilde Key (~) drops down the translucent interactive console. Developers can execute arbitrary Lua commands live during gameplay: 

] lab_set_gravity(-9.8)
[Lua] Gravity adjusted to -9.8 m/s^2
] Balance.Player.walkSpeed = 12.0
[Lua] Player walk speed adjusted to 12.0 m/s (Super Sprint)
] lab_spawn_bot("t-800", 0, 2, 5, "Minigun")
[Lua] Spawned T-800 bot with Minigun at (0, 2, 5)

4. C++ / Lua C-API Engine Hooks & Camera Control

The C++ engine registers functions and namespaces into the Lua global environment via lightweight C wrappers. This includes real-time camera switching, HUD bindings, entity scripts, and trigger callbacks: 

-- Camera Object & Scene Control API:
Camera.setActive("cam_tpp")     -- Switch active camera by name
local curCam = Camera.getActive() -- Returns current active camera name ("cam_tpp")
Camera.setFov(85.0)             -- Dynamically adjust field of view
Camera.setPosition(0, 3.5, 10)  -- Reposition camera in 3D scene
Camera.setRotation(0, 180, 0)   -- Set Pitch, Yaw, Roll

-- Lifecycle & Trigger Hooks:
function OnUpdate(dt)
    -- Called every frame tick with delta time
end

function OnTriggerEnter(entityId, otherEntityId)
    -- Called when entity overlap or proximity event occurs (doors, pickups, triggers)
    if otherEntityId == 1 then
        HUD.setText("rpg.quest_status", "ZWOJE 1/5")
    end
end

5. Sandbox Safety & Live Script Reloading

Executing lab_reload_scripts() flushes and re-evaluates all Lua files on the fly. If a script contains syntax errors or infinite loops, the pcall protected environment safely intercepts the error and logs it to the in-engine console without crashing the application.
