1. Network Architecture & Topologies

Multiplayer in Lab Engine is built around a strict client-server authoritative architecture. The server owns all game state, physics calculations, player positions, projectile hits, and health values. Clients send raw input commands (movement directions, view angles, jump and fire actions) and immediately simulate movement locally to ensure zero perceivable latency.

2. Lightweight UDP Packet Protocol

The engine uses raw UDP datagrams without bloated third-party transport layers. Packets are binary-encoded using compact structs:

  • ConnectRequest / ConnectAccept: Handshake packets exchanging client callsign, protocol version, and assigned ClientID.
  • ClientInputPacket: High-frequency 64Hz input packet carrying sequence numbers, pitch/yaw, movement intent vectors, and weapon trigger flags.
  • NetServerSnapshot: Periodic authoritative broadcast containing the current server tick, authoritative position, velocity, active players, and bullet impact events.

3. Dedicated Server Architecture (LabServer.exe)

LabServer.exe runs headless on Linux or Windows without initializing an OpenGL context or audio device. It loads the map's .labmap file, compiles solid polyhedral collision boxes, and executes a deterministic 64Hz simulation loop: 

// 64Hz Fixed Simulation Tick in DedicatedServer
void DedicatedServer::update(float dt) {
    _tickAccumulator += dt;
    while (_tickAccumulator >= 0.015625f) { // 1/64 sec
        _currentTick++;
        processClientPackets();
        updatePlayerPhysics(0.015625f);
        updateCombatAndProjectiles(0.015625f);
        broadcastSnapshot();
        _tickAccumulator -= 0.015625f;
    }
}

4. Client-Side Prediction Architecture

To eliminate the feeling of lag, the client does not wait for server confirmation before moving. When the player presses W, local physics calculates the displacement immediately, stores the move in an input history buffer, and sends the command sequence to the server.

5. Server Reconciliation & Ground Clamping

When an authoritative snapshot arrives from the server, the client compares its historical predicted position at that server tick with the authoritative state.

If a discrepancy exceeds a tolerance threshold (e.g. pushed by an explosion or bumped into another player), the client reconciles:

  1. Snaps the player's position to the server authoritative position.
  2. Re-clamps the player stably to the solid brush floor (zero penetration).
  3. Re-applies all unacknowledged client input packets from the history buffer forward to the current frame.

This guarantees that even under network jitter or packet loss, movement remains responsive and cheat-resistant without rubber-banding.

6. World State Delta Snapshots

Snapshots broadcast the state of all connected clients (position, eye rotation, alive status, equipped weapon ID, and health). Remote entities are smoothly interpolated between the last two received snapshots via cubic Hermite splines.

7. LAN Broadcast Discovery & Server Browser

Running servers broadcast a lightweight UDP beacon on port 27020 every 1.5 seconds containing server name, map name, player count, and max capacity.

The in-game Server Browser listens for these datagrams, measures round-trip ping, and renders clickable server entries allowing players to join matches with a single click.
